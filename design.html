01

設計定位

一間貓舍的網站要同時說服兩種人：想找一隻健康幼貓回家的飼主，以及評估血統與繁育品質的同業。高級感不是金色和黑底，而是克制、秩序與對細節的在意。

Quiet

安靜的畫面

大面積留白、單一主色、極少裝飾線。每一屏只講一件事，讓視線停在貓咪身上。

Editorial

雜誌式排版

襯線中文標題搭配無襯線內文，照片以 4:5 直式為主，版面像一本精裝的育種圖鑑而不是電商列表。

Trust

可驗證的信任

血統書、疫苗、基因檢測不藏在文字裡，而是以清楚的資料卡呈現。狀態標示永遠一致，不讓飼主猜。

風格參考關鍵字

精品珠寶官網的留白節奏· 攝影集畫冊的照片比例· 高級飯店的預約流程· 育種協會文件的資料嚴謹

02

視覺系統

色彩、字體、間距與質感的規格。所有頁面與元件都從這組 token 衍生，不另外取色。

色彩

底色取自宣紙與月白，而非純白，讓照片的白毛與畫面有層次差。主色「煙燻琥珀」只用在一處強調、連結與分隔符號，面積控制在畫面的 5% 以下。狀態色獨立於主色，避免「可預約」看起來像裝飾。

間距、圓角與質感

Spacing

8px 基準格。區塊間距 96 / 128px（手機 64px），卡片內距 24px，內容欄最大寬度 1180px，單欄文字寬度 66 字。

Radius

按鈕與輸入框 4px，卡片與照片 10px，狀態標籤全圓。不使用大圓角，維持精裝書的方正感。

Surface

陰影只用在懸停的卡片與彈出層，數值低、擴散大。分隔以 1px 線條與底色深淺切換為主，不堆疊卡片。

影像規範

  • 幼貓與種貓主圖固定 4:5 直式，首頁大圖 16:9 或 21:9，相簿 1:1。上傳時後台自動裁切並產生三種尺寸。
  • 統一調色方向：自然光、低對比、略偏暖的灰。避免高飽和濾鏡，避免文字壓在貓臉上。
  • 影片採無聲自動播放的短片（6 到 10 秒），點擊後展開含聲音的完整版。
  • 所有素材由客戶提供（報價單注意事項第 4 點），設計書只規範比例與調性。
03

元件規範

全站共用的按鈕、狀態標籤、幼貓卡與表單欄位。這些元件在前台與後台外觀一致，只差操作權限。

按鈕

預約看貓 → 加入候補名單 送出詢問 查看領養流程
  • 主按鈕（墨色）：每頁只出現一顆，對應該頁最重要的動作。
  • 線框按鈕：次要動作，與主按鈕並列時放右側。
  • 琥珀按鈕：只用於表單送出，讓「送出」在長表單中可被找到。
  • 文字按鈕：內文中的導引，底線用琥珀色。
  • 字距 .12em，高度 44px，手機上全寬。懸停上移 1px 並加深，無其他特效。

狀態標籤

可預約 已預訂 已送養

三種狀態對應報價單「幼貓找家」的規格。顏色之外一律附文字，色弱使用者也能辨識。已送養的幼貓不下架，改以灰階呈現並進入「送養相簿」，成為貓舍的實績。

內容順序

狀態 → 名字 → 品種／花色／性別 → 出生日期與週齡。週齡由出生日期自動換算。

互動

整張卡可點擊；懸停時照片放大 3%，若有影片則改播放短片。

空狀態

底線式輸入框，聚焦時底線轉為琥珀色。錯誤訊息直接寫在欄位下方，說明怎麼修正。從幼貓詳情頁進入表單時自動帶入該貓名字。

1選擇幼貓或候補→ 2稱呼與聯絡方式→ 3居住環境與養貓經驗→ 4期望參觀時段→ 5送出，顯示 Line 加好友
Form design

單頁長表單，分四個小節以細線分隔，不做分步精靈。必填只有稱呼、聯絡方式、想詢問的對象三項，其餘選填，降低手機上的放棄率。送出後頁面顯示「我們會在一個工作天內透過 Line 聯絡您」與 Line 加好友連結，並寄 Email 通知貓舍主人。

Waitlist

候補名單是同一張表單的變體：第一題改為「偏好的花色與性別」。後台以「候補」分類顯示，當新胎上架時，主人可一鍵複製候補者聯絡清單。Line 自動通知不在本次範圍（報價單注意事項第 3 點），因此通知動作由主人手動進行。

領養流程與須知 /adopt

以縱向時間軸呈現六個步驟：線上詢問、預約參觀、確認與訂金、等待離家（12 週）、接貓日、終身諮詢。每步一段 60 字以內的說明。下方放「領養須知」手風琴：費用包含項目、健康保證、退換政策、不開放的情況。文案由客戶提供。

對應報價單專區 6。技術選型以「客戶自行上架免費」為前提，後台必須夠簡單、主機費用必須夠低。

層級建議理由
前端Next.js（App Router）＋ TypeScript靜態產生幼貓與種貓頁，SEO 與載入速度好；狀態更新時增量重新產生
樣式CSS 變數 token ＋ Tailwind 或 CSS Modules本設計書第 02 章的 token 可直接落為 CSS 變數
內容與後台Supabase（Postgres、Auth、Storage）自建後台，或 Sanity / Payload CMS以「胎、幼貓、種貓、詢問」四張表建模；圖片轉檔在上傳時處理
圖片Next/Image ＋ 物件儲存 ＋ CDN自動 WebP 與多尺寸，首頁大圖預載
部署Vercel 或 Cloud Run，自訂網址，Let's Encrypt HTTPS免費或低月費方案即可承載貓舍流量；網址與主機年費由客戶負擔
通知表單送出寄 Email 給主人（SMTP relay）Line 自動通知不在本次範圍，日後可加
上線檢查Lighthouse、各裝置實機測試、表單端到端測試、OG 預覽驗證對應報價單「基本測試與上線檢查」
